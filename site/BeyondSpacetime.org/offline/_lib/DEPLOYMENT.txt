BeyondSpacetime.org v1.9.0 — Offline Scientific Education Edition

Install the cumulative ZIP into the existing document root after backup. This is an additive upgrade, not a complete replacement for the original v1.2.0 root website (unavailable in this session). All 254 files in the v1.8.0 archive are unchanged. The Offline-only ZIP adds /offline/ and can be installed independently; its local teaching catalog is self-contained, but links to prior modules require those modules to be deployed. Add an Offline Learning navigation link to /offline/. Add that single canonical URL to the root sitemap when the original root source is available. No root files are modified.

Architecture: static HTML, CSS, JavaScript, manifest and scoped service worker; no production PHP execution needed for offline learning. The local solver is a port of foundations/_lib/model.php v1.3.0, with 12 models and 144 cross-language-independent PHP/JS fixture comparisons using an absolute/relative tolerance 2e-12 * max(1,abs(a),abs(b)). The exact global/catalog.json language data and foundations/catalog.json lesson data are retained in the local catalog. The lesson texts, charts, terminology and parameter labels support English, Spanish and French; the app shell and notebook controls remain primarily English. Independent scientific translation review has not been performed.

Deployment: HTTPS on the canonical domain, no rewrite of existing files/directories, DirectoryIndex index.html for /offline/, correct JavaScript and manifest MIME types, and no public access to /offline/_lib/. Keep offline/.htaccess and offline/_lib/.htaccess on Apache; on Nginx explicitly deny /offline/_lib/ and serve the real directory/index.html. Ensure the host's CSP permits same-origin scripts, styles, workers, and the manifest (worker-src 'self', manifest-src 'self' if these directives are used). No CDN/runtime libraries or external API calls needed. Do not serve sw.js as HTML or redirect /offline/ to a different origin. Configure no-cache for sw.js. Service worker scope is /offline/ only; it intercepts only the ten exact local GET URLs listed in sw.js. No API calls, user submissions, cross-origin URLs, root pages, YouTube or book downloads are cached. Avoid a root-level service worker conflict; inspect existing registrations.

Acceptance test on the live HTTPS site (required before promising offline access):
1. Open /offline/ online. Read a lesson and run its reference control.
2. Select Prepare offline. Wait for the verified ten-resource readiness report. Install using browser menu or the optional install prompt when supported. Installation eligibility and UI vary by browser/OS.
3. Turn off connectivity, close and reopen the installed app or navigate to the exact /offline/ URL. Verify CSS, all three lesson languages, calculations, charts and saved notebook. Test an actual mobile device as well as desktop. Direct navigation in the development harness was blocked, so this live test is not yet completed.
4. Save and export an investigation, reload it offline, and verify its recalculated metrics. Progress and up to 30 recipe entries are stored in browser localStorage. Storage may be denied, evicted or cleared; export to preserve your work. No synchronization. Clearing the app cache does not clear progress/recipes. Separate controls delete them explicitly. Cache removal requires reported online connectivity.
5. Reconnect. Test Check for update after publishing a new version. Bump the cache name AND the catalog version whenever changing cached resources. Updates install into a new cache; old caches remain until activation, and the UI offers Apply update when waiting. Browser may activate a waiting update after all old tabs close. Failed installation deletes the new version cache, not the old version. Publish coherent assets atomically where possible. The cache readiness check detects presence, not cryptographic authenticity. Never reuse the same cache version for different content.
6. Verify prior modules and root site operate independently. Test /offline/_lib/test.js returns 403 or 404. Check actual production headers, service-worker registration, MIME and console errors. No live deployment, full PWA installability, accessibility certification, security audit or indexing verification was performed.

Scientific scope: educational conditional calculations; not an observational fit. Offline import accepts the local recipe schema or an exported offline investigation, not arbitrary /research/ multi-case recipes. Imported numerical results are ignored and recalculated. JSON export contains the exact normalized parameters, all numerical rows, source solver SHA-256, limitations and source URL. CSV contains the sample table only. No exact bitwise equivalence across JS/PHP is asserted. Original publications remain on ArcSecs.com.
